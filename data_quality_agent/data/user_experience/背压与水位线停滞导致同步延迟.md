# 案例：背压与水位线停滞导致目标表持续落后

## 背景
`ods_orders` 与 `dwd_orders` 数据量差异逐日增大，目标表始终落后源表，
校验平台告警的差异量随时间累积。

## 现象
- 目标表最新数据时间明显落后于源表。
- 差异不是某一天缺口，而是持续的“追赶不上”。

## 排查步骤（Flink UI）
1. Flink UI → 作业拓扑：某算子背压状态为 HIGH，上游数据积压。
2. Flink UI → 指标：Source 端 Watermark 停滞不前，
   currentFetchEventTimeLag 持续增大。
3. Flink UI → 指标（Kafka 消费组）：消费 lag 增长，或某分区长期不前进。
4. Flink UI → 资源指标：TaskManager CPU 打满或频繁 Full GC，吞吐下降。

## 根因
作业存在背压瓶颈（算子效率低或资源不足），消费速率跟不上生产速率，
数据在链路中积压，目标表持续落后源表，差异随时间累积。
若上游本身停止生产，则表现为水位线停滞且目标表不再增长。

## UI 检查项与判定标准
- 背压状态：HIGH 说明瓶颈算子所在。
- Watermark / lag：停滞或增长说明数据积压，而非作业失败。
- 资源指标：CPU/内存/GC 判断是资源不足还是算子效率问题。

## 修复建议
- 提高瓶颈算子并行度或扩容 TaskManager 资源。
- 优化 SQL：减小维表查询压力、合理设置维表缓存、避免数据倾斜。
- 为消费 lag / 水位线配置监控告警，滞后超过阈值提前介入。
